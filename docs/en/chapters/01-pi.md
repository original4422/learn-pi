# 01 · Meet the real Pi first

<p class="eyebrow">STAGE 01 / A FOUNDATION, NOT A BLANK CANVAS</p>

This chapter produces a read-only Pi session that can inspect the sample project and explain its code and tests. You are not adding your own agent loop: Pi handles model tool selection, tool execution, and returning results to the model.

## No-key stage experiment

This runs real Pi with a scripted provider in a fresh exercise workspace and asserts this stage’s behavior. It makes no remote model request.

```sh
npm run stage -- --stage 1
```

## What Pi already provides

The pinned `0.85.1` release includes model access, the tool loop, streaming events, sessions, compaction, instruction files, Skills, and tools such as `read`, `write`, `edit`, and `bash`. Extensions register tools and commands, observe lifecycle events, and intercept calls. The SDK composes these capabilities inside your own application. The course does not claim these native features as inventions. See [versions and sources](../reference/sources).

Distinguish **available tools** from **active tools**. Pi supporting writes does not require every lesson to expose them. `src/stages.ts` chooses capabilities, `src/runtime.ts` creates the real session, and `src/extensions/course.ts` installs the extension. Stage 1 exposes bounded reading and directory listing.

## Why start with a thin entry point

Starting with a homemade `while True` loop risks teaching a generic agent instead of Pi. We keep Pi's loop and change its tool surface and host interaction. Each later chapter extends the same application rather than replacing it with an unrelated demo.

```text
User input
   ↓
Course CLI → Pi AgentSession → Model provider
                 ↑                 ↓
                 └── Tool result ← Tool call
                         ↑
                Extension and policy
```

`AgentSession` is the running session; `SessionManager` manages its record. Model-generated arguments are a request, not proof an action occurred. A completed tool event is stronger evidence than an assistant saying it read a file.

## Run stage 1

```sh
npm run lab:reset
npm run agent -- --stage 1 --workspace examples/workspaces/todo
```

This interactive path requires configured model credentials. Enter:

```text
Read this project and explain the task data structure and existing tests.
List the directory first, then read only necessary files. Do not modify anything.
```

Use `/status` to inspect the stage and mode; `/quit` exits. Without a key, run `npm run demo` and `npm run test:integration`. They use real Pi with scripted model input, verifying runtime connectivity rather than model understanding.

To see the native extension-loading path, run this at the repository root:

```sh
PI_CODING_AGENT_DIR="$PWD/.cache/pi-agent" LESSON_STAGE=1 npm exec pi -- --no-extensions -e ./src/extensions/course.ts
```

This starts Pi in the current directory. Understand that working-directory choice before doing experiments; use the SDK entry point's explicit `--workspace` for the disposable project.

## Follow the call chain

Read `src/cli.ts` → `src/runtime.ts` → `src/stages.ts` → `src/extensions/course.ts`. Ask who parses input, who creates the session, who selects tools, and who prevents inadmissible calls. These are separate responsibilities.

The essential SDK shape is below; `src/runtime.ts` contains the complete configuration:

```ts
import { createAgentSession } from "@earendil-works/pi-coding-agent";

// The application also supplies resources, session management, and tools.
const { session } = await createAgentSession({ cwd: workspace });
try {
  await session.prompt("Explain the project before changing anything.");
} finally {
  session.dispose();
}
```

`await session.prompt()` drives Pi's session and tool loop rather than making a direct model HTTP request. `finally` releases session resources.

## Verification and failure cases

Run `npm run test:integration` and observe a real session loading the extension, emitting events, and executing tools. Then ask stage 1 to create a file. The tool surface should not offer writing, and a persuasive prompt must not grant permission. The model may explain that it cannot comply; inspect the fixture to establish whether any file changed.

If startup reports missing credentials, fix provider configuration. Do not remove authentication checks or present scripted text as a model response. If Node is unsupported, select Node `>=22.19.0` as described in the quickstart.

**Completion criterion:** distinguish assistant output from actual tool execution; identify Pi's native capabilities; confirm stage 1 leaves sample source files unchanged.

## Design connection

In a complete coding agent, reading a file appears as a single product action. Here you can inspect the request, policy, and result independently. That is a useful engineering perspective on Codex/Claude Code-style products, not a reproduction of their internals. Next we turn “plan first” from a prompt into runtime state.
