# 01 · 先认识真实 Pi

<p class="eyebrow">STAGE 01 / 底座，不是空白画布</p>

本章的产物是一个只读的 Pi 会话。它能查看样例项目，并说明代码和测试的关系。你还没有添加“自己的 Agent 循环”：模型选择工具、执行工具、把结果送回模型，这些都交给 Pi。

## 无 Key 逐章实验

这条命令使用真实 Pi 与脚本化 Provider，生成独立练习目录并断言本阶段行为；不调用远程模型。

```sh
npm run stage -- --stage 1
```

## Pi 已经提供什么

锁定版本 `0.85.1` 的 Pi 已有模型接入、工具循环、流式事件、会话管理、上下文压缩、指令文件与 Skills，以及 `read`、`write`、`edit`、`bash` 等工具。扩展可以注册工具和命令、监听生命周期并拦截调用。SDK 则让你在自己的应用里装配这些能力。课程不会把它们重新命名为原创功能。版本、包名及上游源码见[来源页](../reference/sources)。

关键区别是**可用工具**与**启用工具**。Pi 能提供写入工具，不意味着每个教学阶段都开放写入。`src/stages.ts` 选择本章的能力，`src/runtime.ts` 创建真实会话，`src/extensions/course.ts` 安装课程扩展。第一阶段只暴露受控的读取与目录查看。

## 为什么先做一个薄入口

若一开始写一个 `while True` 工具循环，很容易学到的是自制 Agent，而不是 Pi 扩展。我们先保留 Pi 的循环，改变工具面和宿主交互。后续章节持续向同一个会话增加能力，而不是每章替换一个互不相干的程序。

```text
用户输入
   ↓
课程 CLI → Pi AgentSession → 模型 Provider
                 ↑              ↓
                 └── 工具结果 ← 工具调用
                        ↑
                   课程扩展与策略
```

`AgentSession` 是会话运行时；`SessionManager` 管理会话记录。模型生成的工具参数是待处理请求，不是已经发生的事实。你看到工具完成事件后，才能说工具实际执行过。

## 运行第一阶段

```sh
npm run lab:reset
npm run agent -- --stage 1 --workspace examples/workspaces/todo
```

这是需要已配置模型凭据的交互路径。输入：

```text
请读取这个项目，解释任务数据结构和已有测试。
先列目录，再只读需要的文件，不要修改。
```

输入 `/status` 检查阶段和模式，输入 `/quit` 退出。没有 Key 时先运行 `npm run demo` 与 `npm run test:integration`；它们使用真实 Pi 和脚本化模型输入，足以验证运行时连通性，不能证明模型理解了项目。

想查看官方扩展的原生装载路径，可以从仓库根目录运行：

```sh
PI_CODING_AGENT_DIR="$PWD/.cache/pi-agent" LESSON_STAGE=1 npm exec pi -- --no-extensions -e ./src/extensions/course.ts
```

这个命令在当前目录启动 Pi。先了解默认工作目录，不要拿自己的重要项目做写入实验。后续 SDK 入口用 `--workspace` 显式指定练习目录。

## 沿调用链读源码

按 `src/cli.ts` → `src/runtime.ts` → `src/stages.ts` → `src/extensions/course.ts` 的顺序阅读。先回答四个问题：谁解析用户输入，谁创建会话，谁决定工具集，谁阻止不合规调用？这四个责任不必挤在一个函数里。

Pi SDK 的核心装配形状如下；完整配置以 `src/runtime.ts` 为准：

```ts
import { createAgentSession } from "@earendil-works/pi-coding-agent";

// 实际项目同时设置 workspace、资源加载器、会话管理和工具。
const { session } = await createAgentSession({ cwd: workspace });
try {
  await session.prompt("Explain the project before changing anything.");
} finally {
  session.dispose();
}
```

这里的 `await session.prompt()` 不是直接向某个模型 SDK 发 HTTP。它驱动 Pi 的会话与工具循环。`finally` 保证结束时释放资源。

## 验证与失败案例

运行 `npm run test:integration`，观察真实 Pi 会话加载扩展、发出事件并执行工具。再在第一阶段请求“创建一个文件”。预期结果是工具面没有写入能力，且策略不会仅凭模型措辞放行。模型可能用自然语言解释无法完成；这不等同于文件被修改，应当检查样例目录确认。

如果启动报缺少凭据，先修复 Provider 配置；不要改掉鉴权检查或用脚本输出冒充模型回答。如果报 Node 版本不支持，按快速开始切换到 Node `>=22.19.0`。

**验收标准：** 你能从实际事件区分模型回答和工具执行，能指出哪些能力由 Pi 提供，能确认第一阶段不会修改样例源码。

## 设计对应

使用完整编程 Agent 时，“读文件”只是一个产品动作。这里把它拆成可观察的请求、策略和工具结果；这是理解 Codex/Claude Code 类产品的工程视角，不是其内部实现的复刻。下一章把“先计划”从一句提示词变成运行时状态。
