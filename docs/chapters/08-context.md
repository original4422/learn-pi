# 08 · 管理上下文，选择隔离边界

<p class="eyebrow">STAGE 08 / 两个问题：模型看见什么，程序能够做什么</p>

上下文控制信息，隔离控制能力。这两件事经常一起出现，但无法互相替代。少读一个文件可以减少噪声，却不会撤销进程权限；放进容器可以限制部分副作用，却不会自动让模型推理更可靠。

## 无 Key 逐章实验

这条命令使用真实 Pi 与脚本化 Provider，生成独立练习目录并断言本阶段行为；不调用远程模型。 本阶段检查实际上下文/统计 API，不伪造在线压缩结果。

```sh
npm run stage -- --stage 8
```

## Pi 已有上下文机制

Pi 已提供指令文件、Skills、提示模板、会话树与压缩。课程不重写它们。`src/runtime.ts` 使用显式 `DefaultResourceLoader`，关闭自动加载的项目/全局扩展、Skills、提示模板、主题和上下文文件，再明确读取经过路径策略检查的工作区 `AGENTS.md`。

这样做是为了让第一次运行可解释：你知道加载了什么，不会因为机器上已有插件而得到不同课程行为。原生 Pi 入口仍遵循 Pi 自身的资源加载机制；不要把课程 SDK 的默认值误认为 Pi 产品默认值。

## 运行上下文实验

```sh
npm run agent -- --stage 8 --workspace examples/workspaces/todo
```

先完成几次只读问答，输入 `/status` 查看上下文与会话统计，然后输入 `/compact`。这会调用 Pi 压缩，保留目标、决策、任务 ID、路径和测试结果等重点。真实摘要通常需要模型调用；无 Key 时不要声称已经验证了压缩质量。

压缩前后检查文件内容：它们不应因压缩改变。再次要求 Agent 说明当前目标、未完成事项与已验证证据。如果摘要遗漏事实，应补回明确状态或重新读取来源，不能把压缩当无损存储。

## 定制方式如何选择

| 需要 | 优先考虑 | 本课例子 |
| --- | --- | --- |
| 给项目提供常驻约定 | 指令文件 | 样例 `AGENTS.md` |
| 可复用的操作知识 | Skill | 阅读 Pi 原生 Skill 机制，课程不自动加载 |
| 可执行工具、事件检查、界面行为 | TypeScript 扩展 | `src/extensions/course.ts` |
| 控制模型、资源、会话与宿主生命周期 | SDK | `src/runtime.ts` |
| 从别的语言驱动 Pi 进程 | RPC | [Python 进阶参考](../reference/python-rpc) |

不要为一段稳定操作说明写一个进程，也不要用提示模板承担强制审批。选择与需求相匹配的机制，才能让边界可维护。

## 容器实验：验证具体限制

仓库提供容器配置；完整命令和机器要求见[实验页](../guide/labs#容器隔离实验)。实验应验证三件事：样例目录可写、镜像根文件系统只读、网络被关闭。课程源码、宿主家目录、认证文件和 Docker socket 不应作为可写挂载暴露给实验。

容器主要限制里面运行的代码。若 Agent 主进程仍在宿主机，仅把测试放进容器，那么宿主上的文件工具与扩展并没有获得同样隔离。本课的配置与报告会明确实际放进去的进程以及未验证项。

容器也不是“绝对安全”：它依赖内核、运行时配置与挂载范围。离线实验不需要传入模型密钥；真实模型接入需要网络，应另行设计最小网络访问而不是取消所有限制。

## 失败与验证

运行 `npm run test:integration` 检查课程加载器与只读子会话的资源配置。容器可用时运行隔离实验并记录实际退出码；不可用时保留可运行配置，报告“未执行”，不能把静态配置检查当成隔离通过。

对上下文做一次故障思考：摘要写“所有任务完成”，任务文件仍有 `pending`，应该信谁？正确做法是重新检查任务与证据，解决冲突，而不是把更短的文字当成更权威的信息。

**验收标准：** 能区分资源加载、上下文压缩、路径策略与 OS 隔离；知道每个实验实际验证了哪一层。

## 设计对应

成熟编程 Agent 将权限、上下文和执行环境分别配置，是因为它们处理不同问题。本课程也保持这种分离。对产品的更多对照与证据日期，见[设计对照](../reference/comparison)。
