# 07 · 修改、验证、审查，再恢复

<p class="eyebrow">STAGE 07 / 让“完成”有文件和测试作证</p>

现在 Agent 能计划、记任务和分派研究，但还缺一个完整编程闭环。本章用一个故意带缺陷的小型 Todo 模块，把读代码、修改、运行测试、审查 diff 与文件恢复连起来。

## 无 Key 逐章实验

这条命令使用真实 Pi 与脚本化 Provider，生成独立练习目录并断言本阶段行为；不调用远程模型。

```sh
npm run stage -- --stage 7
```

## Pi 原生工具之外还需要什么

Pi 已提供 `read`、`write`、`edit`、`bash`。我们不重新实现编辑器，而是增加两项课程能力：`verify_project` 用固定参数运行样例测试并返回 Git 差异；检查点工具只在带课程标记的可丢弃工作区操作。官方已有 Git 检查点示例，本实现额外强调目录、元数据和恢复范围的显式验证。

固定测试命令也会执行项目代码，所以它仍需要执行模式与审批。不能因为名字叫“验证”就把它自动归类为安全读取。

## 先观察故意失败的样例

```sh
npm run lab:reset
npm run agent -- --stage 7 --workspace examples/workspaces/todo
```

样例 `todo.ts` 的 `addTodo()` 尚未去掉首尾空白，也不拒绝空白输入。`todo.test.ts` 已写出要求。保留公共 API，不要改测试来掩盖问题。

在计划模式下要求 Agent 读取实现与测试，说明失败原因和最小修复。然后由你执行：

```text
/mode execute
/checkpoint before-trim-fix
```

记录返回的检查点 ID。让 Agent 先调用 `verify_project`，确认失败；再修改实现，再验证并审查 diff。你应看到输入修整和空值检查，而不是新依赖、API 改名或测试删除。

## 读代码时抓住三条证据线

`src/verification.ts` 使用 `execFile` 与固定参数启动测试，不拼接 shell 字符串。返回 `passed`、有限长度的输出、diff 与 status。失败输出不能简单变成抛错后消失，否则模型无法据此修复。

`src/core/checkpoints.ts` 检查课程标记、规范化根路径和独立 `.git` 目录，拒绝任意 Git revision。创建快照使用私有 index 和 `refs/learn-pi/` 引用，不移动普通 `HEAD`；恢复只接受清单内的检查点 ID。

```ts
const before = await checkpoints.create("Before repair");
// 编辑并运行测试；恢复是一个独立、需要授权的动作。
await checkpoints.restore(before.id);
```

这是实际存储 API。恢复将样例文件树恢复为快照，包括删除快照之后新增的普通文件。因此不要把个人材料放进练习目录。`.learn-pi`、受保护的凭据路径和仓库元数据不参与普通样例恢复。

第三条是 `src/extensions/course.ts`：模型调用的创建/恢复工具仍经过策略和审批；人类输入的 `/restore ID` 也会明确确认恢复范围。

## 三种“恢复”不能混用

| 操作 | 改变什么 | 不会自动改变什么 |
| --- | --- | --- |
| Pi 会话分支/切换 | 对话历史的活动路径 | 项目文件、任务快照 |
| 上下文压缩 | 模型下一次看到的上下文 | 工作区文件 |
| 课程检查点恢复 | 可丢弃样例中的普通文件 | 对话、任务元数据、父仓库 |

恢复后模型可能还“记得”修复成功，因此应重新读文件和运行测试。不要指望文件回滚自动修正模型记忆。

## 失败实验

在 `npm test` 中检查恢复新增/删除文件、拒绝未知 ID、拒绝符号链接、父仓库不受影响和受保护文件保留。检查点不是通用备份系统：并发外部写入、进程崩溃中的多文件恢复以及损坏的磁盘不在原子事务保证内。

手动完成修复后输入 `/restore` 加之前的真实 ID，确认后重新验证。预期是两个故意设置的测试再次失败。这证明你恢复了文件，而不只是修改一个任务状态。

**验收标准：** 看见“失败 → 最小修复 → 测试通过 → diff 符合预期 → 恢复后重新失败”的完整证据链。

## 设计对应

编程 Agent 的价值最终要落在可审查的改动上。这里采用测试与 diff 作为验收材料，检查点作为实验恢复手段。它们与成熟产品的工作流需求相似，但本课程不会把一个教学检查点称为完整的撤销、备份或多 Agent 合并系统。
